# 2026-10-04 黑屏与进度晃动调查

用户报告：已交付 ARM64 测试包播放所有画面黑色，声音正常、播放进度在走动，进度条不稳定。没有取得华为设备的现场日志，因此不能把特定驱动故障认定为已确认的真机根因。

代码与既有证据确认的缺口：

- 旧集成测试仅检查 mpv 内部截图，没有检查 Android 实际显示窗口。新增回归检查通过系统截图采集视频区域，并比较原画与增强。
- 默认 `mediacodec` 通过 AImageReader / HardwareBuffer / 外部 EGL 纹理显示；复制硬件解码及软件解码走不同路径，不能用一条模拟器路径代表全部设备。
- 固定内核的 EGL helper 为 GLES 请求 client version 2，而应用声明最低 GLES 3；旧 Swiftshader 返回 GLES 3，不代表真实驱动的上下文版本。
- GPU shader cache 的错误状态会保持，普通增强参数提交或切换原画没有重建渲染器。新增故意损坏 shader 的回归检查，要求实际屏幕恢复显示。
- UI 把缺失的 time-pos 样本填为 0；状态栏文字可换行，进度控制栏高度可能随状态变化。新增缺失样本回归，要求已有进度不跳回零。

验证策略：先在旧生产代码上运行上述回归，保留失败记录；再验证修复版本的实际屏幕、增强设置、软件/硬件复制解码、定位/暂停/倍速、shader 故障恢复、ROI 以及导出。真机状态继续单独记录，不以模拟器结果替代。

旧生产代码回归 run `37144900225`：4 项测试中 2 项失败，明确复现缺失位置跳零与坏 shader 不能恢复。旧代码在模拟器上的系统窗口原画/增强仍可见，因此尚未直接复现华为所有视频黑屏。

独立审查提出两处重要问题：原画 bypass 的正常回执不能掩盖 GL 错误；暂停逐帧后退不能被防抖过滤。已修正原生回执错误优先级，UI 仅根据正常回执显示原画恢复，并增加第二次 shader 故障和暂停时间倒退验证。新增 1080p H.264 / 10-bit HEVC 的实际窗口原画与增强检查。
