# LumaView Mobile 0.1.0-test 验证范围

本分支恢复官方 mpv-android 固定提交 `fdf74f6830c47dbaa8a22ac79726e8303f1db5af` 的应用源码，保留 `is.xyz.mpv` JNI 命名，Android 应用包名为 `org.lumaview.mobile`。原生基础依赖复用 Actions run `37127934301`；重编译固定 FFmpeg 以启用 MP4 muxer、固定 mpv 内核上的 LumaView 补丁及 JNI。不会合并到 main。

应用入口包含可见播放、暂停、跳转、倍速、音量、背光、轨道与旋转控制；触控／鼠标 ROI 选框、应用／取消、裁剪及放大平移；GPU 选区低光增强与原画对比；A/B 双手柄、输入时间、边界预览与循环；原码流和 H.264/AAC 重编码导出。

## 自动化证据的含义

- `CoreTest` 检查黑边、选区坐标、区间与曝光参考数学。数学测试不代替 GPU 像素测试。
- `PlaybackTest` 在真实 x86_64 APK 中调用 libmpv、读取实际暂停／速度／裁剪状态，并用 PixelCopy 保存同帧原画与增强结果。
- `ExportTest` 在 Android 中实际运行 FFmpeg JNI 和 Media3 Transformer，保存输出文件与实际编码器摘要，并检查取消发生于排队入口前的情况。
- `verify_exports.py` 对保存的导出文件完整解码，比较复制模式包负载哈希、编码类型、尺寸和重编码时长。包哈希检查不等于音画同步听音检查。
- APK 构建验证包括签名、包信息、ZIP 16 KB 对齐及每个 ELF LOAD 段对齐。静态对齐与 16 KB 页面设备运行是不同结论。
- Workflow 的 emulator job 使用 Android API 35 x86_64 模拟器。所有此类证据标为模拟器，不能作为 ARM64／华为手机实测证据。

## 当前实现边界

- APK 为可安装调试签名测试包；每次 runner 的签名证书可能变化，尚未建立稳定发行签名。安装跨次构建版本可能需要卸载旧包。
- 原码流模式仅接受可证实 IDR 的 H.264。起点回退至前一个 IDR，末尾延展到下一 IDR／完整文件末尾，以保存闭合 GOP 的解码依赖。确认窗显示请求和实际区间。HEVC 原码流复制暂不支持，应选择兼容的精确重编码模式。
- 原码流允许选择一条音轨；精确模式使用文件默认视频／音轨，可选择无音频；不保留字幕、额外轨道，不写入播放增强、ROI 或用户临时旋转。精确模式限定 SDR，剪辑 API 的时间分辨率为毫秒，最终边界仍受视频帧／音频编码帧粒度影响。
- 自动曝光、暗部处理、空间降噪和高光曲线已实现。尚未完成完整颜色空间／纹理格式参考精度、已知噪声与细节保留数值验收，也未验证 4K 工作纹理预算和长期热性能。模式和旁路状态通过渲染端日志回执显示；不具有方案中完整的统计数值回执 ABI。
- 未实现完整的设备负载自适应质量控制、全套媒体键／后台音频服务、递归文件浏览、多条最近列表、完整选中轨道的精确导出映射或局部放大的剪辑时间轴。
- SAF 输入只读缓存，目标必须能确认是新建空文档；身份或大小无法确认的提供方会拒绝保存，并保留可重试暂存文件。尚未完成真实提供方授权撤销、磁盘不足、所有别名 URI 和故障注入矩阵。
- 部分自动化直接调用播放器属性，不能据此声称所有真实触控、鼠标、辅助功能或生命周期压力验收已经通过。
