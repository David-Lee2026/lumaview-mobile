# 验收数据、证据与性能口径

版本0.1。本文件定义执行时怎么测，不是测试报告。全部性能与画质阈值均来自已确认规格；所举素材、命令和时间窗是待执行流程。

## 1. 测试分层

| 层级 | 能证明什么 | 不能代替什么 |
|---|---|---|
| H：主机数值／状态回归 | 坐标数学、输入合法性、状态机、降级时间窗、参考算法 | 真正手机GPU输出、触控事件分发、硬件解码、听音 |
| A：APK内的设备／模拟器测试 | 实际View触控、JNI调用、取到的GL输出与文件导出 | 不同GPU／ABI兼容和Mate20X热表现 |
| P：目标物理设备 | 本机安装、真实微光观感、扬声器、持续掉帧／发热 | 所有安卓或全部鸿蒙机型保证 |
| B：构建与发布检查 | 固定源、依赖、对齐、签名、对应源码和sha | 播放可用、增强已生效 |

所有报告附层级；失败与BLOCKED保留。T01的基础native冒烟和T07的恒等stage属于检查点，不是E01画质通过。

## 2. 测试素材清单

T01创建生成器与最小短H.264有声／无声素材并锁hash；T04、T08、T09、T13、T14、T15在首次测试前追加各自所需素材与验证脚本；T18补全整机矩阵，不让前置任务反向依赖T18。所有合成内容由host工具离线生成；用户真实视频不进入源码／公共CI。

| 素材ID | 生成或选用内容 | 主要用途 |
|---|---|---|
| FIX-GRID | 带源像素坐标／格点标记的1920×1080、1080×1920、方形及SAR变体 | R04/R05坐标和单次裁剪 |
| FIX-ROI-OUTSIDE | 中央固定暗块ROI，远离ROI边界背景分段由黑到白；另留≤5%上下文带不变 | E02外部独立性 |
| FIX-ROI-INSIDE | 背景不动，ROI内部亮度至少三个台阶且在未到增益上限区间 | E03自动响应，防固定曝光假通过 |

## 3. 画质计算口径

E01取相同解码帧ID／PTS与视口的处理前后视频像素；屏幕亮度不变。暂停帧执行模式切换，记录回执代次后才读图。UI整体截图和背光照片不是默认数值来源。

E02/E03一起执行：外部黑白条件下计算同一暗ROI的曝光差，要求≤0.05EV；随后只让ROI变暗，在没有碰到上限时验证曝光有响应。默认context权重0，不得在测试时关context、发布时又悄悄加上全局统计。

E05参考干净已知图，先把输出除以可比的局部增益／已知映射，比较残差方差；下降目标≥15%，同时标准边缘对比保留≥90%。记录处理前后所有中间指标，不能把本来变亮导致的方差上升或一味模糊当作通过。真实素材没有干净真值时不计算“真实PSNR提升”。

E06归一化每帧输出，新增饱和像素比例=处理后饱和比例−对照饱和比例，限值0.005（0.5个百分点，不是50%或0.5%相对增幅）；曝光、范围及色彩空间需一致。饱和判断门槛和量化精度随素材配置锁定，伴随检查色相、边缘光晕。

E07固定场景预热后每秒曝光变化≤0.05EV；换镜头、seek、重选ROI、旋转、Surface重建分别检查historyEpoch，不能仅测一个事件。相同PTS重复呈现不使历史按UI帧率不断演进。0.4秒平滑与1EV/秒上限是参数，不代替输出稳定性检验。

E08用CPU双精度参考对照设备实际的float／RGBA8编码输出，EV误差≤0.05；log2负值须先可逆编码而非写入RGBA8被截断。全黑、无样本、NaN/Inf注入产生有限输出及无效标识，不伪装有效曝光。

## 4. 剪辑计算口径

内部区间固定为[A,B)。目标精确剪辑参考：首个保留帧为PTS≥A的首帧，末个为PTS<B的末帧；VFR按实际帧序比较，误差目标≤1帧。连续画面位于区间边缘的呈现覆盖要注明，不用固定1/fps取整代替。

T03同容器复制：对每个导出视频包按源轨道、PTS/DTS映射及压缩payload hash匹配；匹配数等于复制包总数，再完整解码输出。跨容器必需表示变换时另做码流内容匹配，报告方法不能继续写“每包原始字节相同”。

T05精确导出：验证实际编码器与每轨处理方式、首末frame-id、没有通过edit list隐藏而残留的前段可见画面。AAC的编码延迟／padding按编码帧粒度另外列出，不用视频帧率评价音频尾部。

T06新增声画偏移=输出事件偏移−源事件偏移，绝对值≤40ms；源已有+120ms偏移的用例需保留而不是归零。实测感知播放偏移与封装时间戳检查分开报告。

T07轨道清单须有用户选中ID、实际解复用index、输出index和处理方式，未保留项在确认时已显示；不能事后日志记下丢轨便视为已告知。

## 5. 性能与温度

主目标本地1080p30 SDR；三种模式original／auto／roi各20分钟，不是三种总计20分钟。记录全程与末5分钟；开播前5秒、主动seek后2秒、缓冲、暂停、失焦不计有效窗口。需保留被排除区间及理由，禁止把所有掉帧时段标成缓冲排除。

掉帧比例使用实际视频呈现／掉帧计数定义和可复核分母；请求30fps但实际未呈现的帧不能从分母丢掉。计数器不能支持完整呈现异常指标时，该指标未测；GPU提交次数、UI刷新或触控刷新不能替代屏幕视频帧率。

掉帧目标≤1%，最长非缓冲停顿≤0.5秒、ANR为0。自动降级后的流畅度结果与原请求档位结果分开：若自动均衡测试降到了原画，F02可证明降级有效，但不能宣称“自动均衡档通过F01”；须报告每档实际生效时长，重新分档验收。

有可靠GPU计时才报告增强阶段P50/P95，P95≤8ms为调校目标；原生硬件计时无效／disjoint／缺扩展用null并标未测。温度／热状态同理。不能仅因系统API没有返回温度就报“低温稳定”。

纹理预算：最长边≤1920并限制单张像素≤2,073,600，避免1920×1920方形素材超出“两张1920×1080”资源意图；两张为最多而非每条路径必须用满。RGBA8路径包括stats/FBO等新增资源总预算约32MiB，浮点64MiB；总进程内存和解码资源另列，无总内存32MiB承诺。

## 6. 实际触控与错误注入

触控通过UiAutomation/Instrumentation或adb测试设备输入到真实View。多指缩放必须注入完整pointerId序列及ACTION_POINTER_DOWN/UP，不能直接调用RoiController当作pinch测试。保存输入路径、屏幕尺寸、density和视频映射回执。

错误注入包括提供方撤权/断开、未知长度流、磁盘预留不足、创建后提供方别名复用、输出写入到一半失败、native Surface失效、编解码器不足和任务强制结束。需要测试用DocumentsProvider，不通过修改用户真实文件／故意写满用户手机来造故障。

## 7. 证据目录与真实性规则

```text
artifacts/runs/<run_id>/
  build.json             # commit、APK、native patch、依赖hash
  environment.json       # API/ABI/GPU/backend/物理或模拟器；无唯一设备标识
  fixtures.json          # 授权来源／生成参数／hash
  Txx/observations.json  # 探针原始观测
  frames/                # 仅合成或获授权可分享的像素输出
  traces/                # 时间戳与事件／帧计数
  export/                # 输出摘要与payload对比，不默认上传个人视频
  results.json           # 38项逐设备状态与证据引用
  report.md              # 结果和局限，保留失败与缺测
```

首部明确build/环境范围；没有实际测量记录时不要创建假的观测文件。软件版本变化后重新运行受影响项；无法证明未受影响的测试也需回归。发布包可不包含所有原始视频，但必须保留可重建合成素材的脚本与hash；个人素材只写用户同意的脱敏摘要。
